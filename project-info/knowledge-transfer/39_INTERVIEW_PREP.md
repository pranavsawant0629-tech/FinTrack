## 2. Core Architecture Questions

### Q1: Why did you choose a federated multi-agent architecture instead of a single monolithic system prompt?
- **Model Answer**: Monolithic prompts that attempt to instruct an LLM on every financial domain suffer from instruction dilution, increased hallucination rates, and lack of bounded safety. In Finova, an options question requires strict SEBI risk disclosures, whereas an SIP question requires deterministic mathematical formulas. Federated multi-agent routing allows each specialist tutor (Equity, Crypto, Derivatives, Personal Finance) to maintain clean system prompts, tailored tools, and explicit regulatory boundaries.
- **Deep Follow-up**: *How does routing work, and does it add latency?*
- **Follow-up Answer**: >90% of routing is fast-path regex and keyword matching in `app/router/central.py`, which executes in **0.6 milliseconds**. Only ambiguous or complex compound queries trigger decomposition.

### Q2: Why are calculations deterministic rather than generated by the LLM?
- **Model Answer**: LLMs are autoregressive probability models, not arithmetic processors. They frequently make rounding errors, fail at multi-period compound interest, and hallucinate options payoff breakevens. In financial systems, mathematical inaccuracy destroys user trust and creates legal liability. By executing all math in compiled Python float arithmetic (`app/tools/calc/`), Finova achieves 100% mathematical precision with sub-millisecond execution.
- **Deep Follow-up**: *How do you prevent the LLM from trying to recalculate the numbers?*
- **Follow-up Answer**: The deterministic tool computes the values first, and the orchestrator injects the exact computed results into the response payload or bypasses the LLM entirely, rendering interactive React cards directly.

### Q3: Why are conversation domains immutable?
- **Model Answer**: In early prototypes, re-evaluating the router on every single turn caused context switching bugs. If a user was discussing equity P/E ratios and casually used the word 'coin', a dynamic router would switch the conversation to the Crypto Tutor, destroying pedagogical continuity. Locking the conversation domain upon creation (Commit `92cae10`) ensures the tutor persona remains stable throughout the learning thread.

## 3. AI, RAG, & Local Inference Questions

### Q4: Why did you select `BAAI/bge-small-en-v1.5` over larger embedding models?
- **Model Answer**: We benchmarked BGE-small (384 dimensions) against E5-large (1,024 dimensions). E5-large added ~80ms of CPU latency per query and required 1.5GB of RAM, while yielding negligible retrieval improvements on structured regulatory text. BGE-small embeds chunks in **6 milliseconds** via FastEmbed's ONNX Runtime, and its compact vector footprint keeps the entire Qdrant vector index under 50MB on disk.
- **Deep Follow-up**: *Why FastEmbed instead of PyTorch with SentenceTransformers?*
- **Follow-up Answer**: PyTorch adds over 3GB of dependencies to the virtual environment and introduces significant cold-start delays on Windows. FastEmbed runs directly on ONNX Runtime using CPU AVX2 SIMD acceleration, providing an ultra-lightweight footprint.

### Q5: How do you enforce citation integrity and prevent hallucinated citations?
- **Model Answer**: We treat the LLM as an untrusted generator. When the model outputs citations (e.g. `[SEBI-EQ-04]`), `validate_citations()` in `app/rag/validator.py` extracts all bracketed tags and cross-references them against the set of chunk IDs actually returned by Qdrant. If the model hallucinates a non-existent citation, it is stripped from the response metadata, and `grounding_status` is downgraded to `partially_grounded` or `ungrounded`.

### Q6: What happens when vector retrieval returns no chunks above the similarity threshold?
- **Model Answer**: In `rag_retriever.retrieve()`, if all cosine similarity scores fall below `score_threshold` (0.5), an empty list is returned. The system prompt is then injected with a strict negative constraint: *"No official regulatory documents were retrieved for this topic. State clearly that you lack verified SEBI guidelines and do not speculate."* The response is marked as `grounding_status="ungrounded"`.

## 4. Financial & Regulatory Compliance Questions

### Q7: How does Finova AI comply with SEBI regulations without an investment adviser license?
- **Model Answer**: Under the SEBI (Investment Advisers) Regulations, 2013, offering personalized buy/sell recommendations, stock tips, price targets, or portfolio allocation for consideration constitutes regulated financial advice. Finova AI enforces a strict educational boundary:
  1. It intercepts all buy/sell and timing queries pre-LLM using regex guardrails in `app/safety/validator.py`.
  2. It displays mandatory statutory non-advisory disclaimers on every assistant turn.
  3. It deterministically attaches the official SEBI F&O risk disclosure (9 out of 10 retail traders incur net losses) to all derivatives explanations.

### Q8: How do you handle market data freshness outside of Indian trading hours?
- **Model Answer**: `MarketClock` tracks Indian Standard Time (IST, UTC+5:30) and the official 2026 NSE holiday calendar. If a quote is requested when the market is closed (nights, weekends, holidays), `MarketDataValidator` classifies the freshness status as `last_traded_close`. If fetched during market hours, it is classified as `delayed` (standard 15-minute exchange delay). If fetched from stale cache during a network outage, it is visibly flagged as `stale_cached_fallback`.

## 5. Security & Privacy Questions

### Q9: How do you prevent Insecure Direct Object Reference (IDOR) attacks in conversations?
- **Model Answer**: On every conversation read, update, message append, or deletion, `ConversationService.verify_ownership()` queries SQLite and asserts that `conversation.user_id == requesting_user_id`. If the identifiers do not match, it logs a security warning and immediately raises an HTTP 403 Forbidden exception before any message data can be serialized.

### Q10: How does Finova protect user PII under the Indian DPDP Act, 2023?
- **Model Answer**: `MemoryValidator.validate_no_pii()` in `app/memory/validator.py` evaluates all candidate user preferences against strict regular expressions for PAN cards, Aadhaar numbers, 10-digit Indian phone numbers, and email addresses. If detected, a `MemoryValidationError` is raised, and the write transaction is aborted before touching `data/memory.db`. Additionally, the platform exposes `DELETE /memory` to fulfill statutory Right to be Forgotten requests.

## 6. Hard Questions an Interviewer Could Ask

### "If Qdrant runs embedded in Python, what happens if multiple processes try to write to it simultaneously?"
- **Answer**: Qdrant's embedded storage mode relies on file-level locks. If two separate OS processes (e.g. two independent Uvicorn worker processes) attempt to initialize `QdrantClient(path="data/qdrant_storage")` with write access, the second process will crash with an access violation lock error. In Finova, writes to Qdrant occur strictly during document ingestion via `scripts/ingest_docs.py` as an offline batch process. During application runtime, Qdrant is accessed purely in read-only search mode.

### "Why didn't you implement streaming SSE (Server-Sent Events) for LLM responses?"
- **Answer**: Full-stream SSE tokens cannot be validated for citation integrity or regulatory safety in real-time without introducing complex chunk buffering. By generating the full response bounded at 600 tokens (~3 seconds), Finova deterministically validates all citation markers, verifies grounding status, extracts structured UI card payloads, and commits atomic SQLite records before emitting the payload to the frontend.

### "What is the single biggest architectural tradeoff you made?"
- **Answer**: Choosing an entirely local, offline architecture. The upside is zero recurring API costs and absolute data sovereignty. The tradeoff is that generation speed is bounded by host GPU memory bandwidth, and the user must install Ollama and download a 4.5GB model file. We mitigated this by ensuring all calculators, safety checks, and market quotes run instantaneously in sub-millisecond Python code, reserving the LLM strictly for conceptual synthesis.
